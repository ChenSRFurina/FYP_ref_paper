先纠正三个容易混淆的概念

  1. 稳定性不是一个概念。可以指优化过程不发散、机身少抖动、受扰后不摔倒，或仿真表现能否预测实机表现。第一篇同时涉及多项，但没有给出“所有状态下都稳定”的形式化保证。
  2. 教师不等于 critic。教师是“训练时掌握更多信息的动作策略”；critic 是“估计未来回报的价值网络”。学生训练也可以使用特权 critic，但部署时不需要 critic。
  3. 在线适应不等于在线更新参数。用最近观测估计 latent 或更新 GRU 隐状态，就可以实现在线适应；不代表机器人边走边在真机上做梯度下降。

1. PPO 更新的是“产生好动作的概率”

训练时，actor 通常给每个关节输出一个动作分布；从中采样动作，以便探索。critic 预测当前状态的未来收益。收集一批轨迹后，用真实得到的回报与 critic 的估计构造优势 Â：这个动作比原先预期好多少。

ρₜ(θ) = πθ(aₜ | oₜ) / πold(aₜ | oₜ) Lclip = E[min(ρₜ Âₜ, clip(ρₜ, 1−ε, 1+ε) Âₜ)] 常见最小化形式：L = −Lclip + cᵥ Lvalue − cₑ H(π)

直觉上，好动作的概率应该提高，坏动作应该降低；clip 限制代理目标对大幅概率变化的激励，减轻更新过猛。它不是一个保证机器人绝不摔倒的约束。价值损失训练 critic，熵奖励维持一定探索。

3. 为什么教师—学生特别适合机器人？

仿真可以直接读取摩擦系数、真实机身速度、地形高度和质量等，真机通常读不到完整真值。教师先利用这些信息学控制；学生再从观测历史或深度图预测 latent 或动作。训练时“开卷”，部署时只能用真实可用信息。

这里有两类明显不同的信息缺口：动力学缺口，如地面打滑和负载变化，常靠历史估计；地形感知缺口，如前方有多宽的沟，常靠视觉蒸馏。相同的“教师—学生”名称，可能对应很不同的工程工作。

4. DAgger 为什么比离线模仿更适合闭环运动？

只录教师的轨迹来训练学生，学生稍有偏差就可能进入教师数据里没有的状态，误差继续累积。DAgger 让学生实际驱动仿真，再在学生到达的状态向教师查询动作标签，并反复训练。它直接处理闭环执行造成的数据分布变化。

5. 神经网络输出关节目标，PD 才计算力矩

常见接口示意：qᵈᵉˢ = qdefault + scale · a τ = Kp (qᵈᵉˢ − q) − Kd q̇

不同论文的 scale、默认姿态、关节顺序和增益不一样，上式是接口示意。50 Hz 的策略更新与更高频的底层控制是两个层次；给另一个型号直接套同一个输出向量和 PD 增益，无法保证行为相同。

读完这一节应能解释：

PPO 学控制，蒸馏补信息缺口；actor 负责动作，critic 辅助训练；部署保留学生与底层控制，不需要把整套训练系统搬上机器人。

MoE 控制策略 + RoboGauge：怎样走得稳，也选得准

Toward Reliable Sim-to-Real Predictability for MoE-based Robust Quadrupedal Locomotion

这篇最接近你说的“稳定性优化”。但它的完整贡献是：改进本体感知控制器的表示能力，并建立跨仿真器的迁移评测闭环。

原文定位：2602.00678v4 · §III–VI；附录 A–C

1. 它发现了什么问题？

仿真训练回报高，并不保证真机稳定。策略可能适应了某个模拟器的接触规律，或者利用奖励中的漏洞：例如完成速度跟踪，却伴随机身振动、关节动作剧烈。只看训练曲线，会把这些策略误判为“训练成功”。

作者把问题拆成两半：策略端用 MoE 提高对不同地形和命令的表示能力；评测端用 RoboGauge 在 MuJoCo 中测跟踪、动作质量和安全相关指标，再选择适合部署的模型。Isaac Gym 训练 → MuJoCo 测试 → 实机验证，形成迭代闭环。

与“先把教师练好，再固定教师训练学生”的常见流程相比，CTS 在同一训练过程中保留教师和学生采样路径。核对官方代码后，可以更精确地理解为：两条路径共享 actor 和 critic，使用不同编码器。教师编码器、共享 actor 与 critic 接受 PPO 更新；学生编码器由 latent 匹配及负载均衡损失单独更新。

在核对的默认配置中，75% 环境走教师路径，25% 走学生路径。共享 actor 同时见到两种 latent，因此学生的执行状态也影响控制器学习。学生编码器在 actor 的 PPO 路径中被停止梯度，不能简单说“所有模块都靠 PPO 端到端更新”。

教师：zᵀ = Eᵀ(sₜ) 学生：zˢ = Σₖ wₖ Eₖ(oₜ₋H:ₜ) wₖ = softmax(g(oₜ₋H:ₜ))ₖ 动作：aₜ = actor([oₜ, z]) 学生编码器损失：Lstudent = MSE(zˢ, stopgrad(zᵀ)) + λbalance Lbalance 论文均衡项：Lbalance = Σₖ (mean_batch(wₖ) − 1/K)²

MoE 在这里混合的是隐变量表示。它没有先训练一个“楼梯动作专家”、再训练一个“草地动作专家”供高层硬切换。gating 对多个专家连续分配权重，得到一个 latent，再交给共享 actor 输出动作。专家分工是学习结果，不能仅凭编号给每个专家命名为某种地形。

6. 训练过程：策略与任务难度一起成长

  1. 并行仿真。Isaac Gym 中 8192 个 Go2 环境，策略 50 Hz，物理仿真 200 Hz；PD 的 Kp=20、Kd=0.5。
  2. CTS + MoE 更新。收集教师 / 学生路径轨迹，更新共享控制器、价值函数、教师编码器，再训练学生 latent 和 gating。
  3. 地形课程。包含平地、波形、坡、粗糙坡、上楼梯、下楼梯、障碍，逐步提高地形难度。
  4. 命令课程。从较小速度范围逐渐扩大；对复杂地形限制命令上限，并提高边界命令的覆盖率。
  5. 动态重采样与奖励课程。避免命令长期互相抵消、机器人没走够距离却无法晋级；逐步放松垂直速度惩罚等。
  6. 域随机化。摩擦、质量、质心、增益、执行器强度、关节偏差和控制延迟等随环境变化。
  7. 定期跨模拟器评测，再决定部署模型。RoboGauge 的选择结果回到训练迭代。

7. RoboGauge：不是再造一个训练奖励，而是独立验收

4. 软约束阶段：允许穿透，但为穿透付代价

如果障碍完全不可穿透，初期机器人反复撞墙，很难遇到能成功通过的状态。作者先让障碍在仿真中可穿透，相当于把“撞上就卡住”的硬限制改成可优化的惩罚，参考直接配点法中的软约束思想。不是在训练过程中用直接配点求解轨迹，也不是允许真机穿透物体。

p 是机器人碰撞体中的采样点；1[p] 标记是否进入障碍；d(p) 是穿入深度。作者在电机密集的髋部、肩部采样更多点，以更强地惩罚这些部位进入障碍。乘 vₓ 是为了减少“快速冲过去、缩短穿透时间从而少受累计惩罚”的漏洞。

每个并行机器人根据上一回合的穿透表现调整难度分数 s，步长 0.05，范围 0–1。障碍参数由 (1−s)l_easy+s·l_hard 插值。通过能力提高，障碍才变难。

1. 难点：在正确的时刻，朝正确的方向起跳

高台、沟和倾斜坡面不仅需要合适的腿部动作，还需要正确的机身朝向。让人拿手柄在临界时刻给方向，误差或延迟都可能导致失败。作者因此不仅蒸馏动作和地形表示，还让深度网络预测所需方向。

与上一篇先学五个专用教师不同，这篇先训练一个以 scandots 和 oracle heading 为输入的多地形策略；再把视觉和方向输入替换为由深度图推断的版本。

2. Scandots 是什么，为什么不用障碍类别？

可以把 scandots 理解为仿真中采样得到的局部地形高度点集合。它提供较通用的几何信息，而不是直接告诉策略“这是某类障碍，高多少、宽多少”。因此面对不规则形状时，表示不完全受人工障碍类别字典限制。

它仍然是训练特权：真机部署时输入是相机深度图，而不是凭空获得无噪声的地形采样点。第一阶段通过廉价的几何输入学习控制，第二阶段再学习从图像获得控制所需表示。

3. 统一奖励：朝目标方向前进，而非紧锁机身坐标速度

d̂w = (p_next − x_robot) / ‖p_next − x_robot‖ r_tracking = min(〈v_world, d̂w〉, v_cmd)

p_next 是下一个 waypoint；v_world 为世界坐标中的二维速度。内积就是速度在目标方向上的投影。沿目标方向运动会得分，偏离甚至反向运动收益更低；到达目标速度后封顶，避免为了多拿奖励无限加速。

这与第二篇的指数误差奖励很不同：指数项强调“和命令向量接近”；这里强调“向目标前进”，给动作与姿态更大自由度。论文同时把世界坐标方向与 waypoint 结合，避免机身坐标下的奖励被不合意的转向行为利用。

为什么不为跳跃写一串关节角目标？

写死后腿收缩、前腿抬升的时间表，很难适应不同障碍。统一奖励只说明应该取得怎样的进展，并用地形与物理约束限制可行行为，让策略自行发现助跑、起跳和落地时的协调。这里的“动作涌现”并非完全没有人工设计：waypoint、地形课程、正则项和观测仍然由人定义。

4. 额外惩罚：少踩边缘，比只看通过距离更可靠

r_clearance = −Σ_四只脚 cᵢ · M[pᵢ] cᵢ = 1 表示该脚接触地面 M[pᵢ] = 1 表示落脚点距地形边缘小于约 5 cm

不加这项时，机器人可能为了节能落在边缘附近。仿真中只差一点也许能站住，实机上感知和执行稍有误差就可能失足。该项把稳健性要求放进训练目标。

注意名字：这里 clearance 指避免边缘接触，不能翻译成“把脚抬高一点”的腾空高度奖励。原公式索引排版有歧义，物理含义是对四只脚求和。

5. 风格奖励：倒立也是一个方向跟踪问题

r_stylized = W · [0.5〈v̂_body-forward, ĉ〉 + 0.5]² 倒立时：ĉ = [0,0,−1]ᵀ；W ∈ {0,1} 是风格开关。

这里 v̂_body-forward 是机身朝前的单位方向向量，不是机器人平移速度。让机身前向轴向下，就能诱导前腿支撑的倒立姿态。训练随机开关 W，部署时由操作者控制。论文对倒立行走还说明采用了不含外感知的训练配置，因此不要把倒立展示与视觉跑酷 checkpoint 混为一谈。

全文还说明使用既有工作的动作正则项。这份论文未列出完整奖励权重表，因此上面三个核心公式不能冒充可直接复现的完整奖励配置。若正式复现，需要继续对照官方训练代码和版本。

4. 怎样从 baseline 发展成一个毕设问题？

可以把研究问题写得很具体：“在固定巡检速度范围与载荷变化下，如何减少机身晃动，同时保持路线通过率与停车精度？”这比“优化稳定性”容易设计实验。

  • 奖励侧：针对机身晃动、动作变化或边缘落脚提出改动，但检查是否损失通过能力。
  • 表示侧：比较历史长度、MoE 专家结构或记忆模块对负载和摩擦变化的适应能力。
  • 评测侧：补充与你们巡检路线一致的地形、载荷和相机运动指标，检验是否更能预测实机表现。
  • 视觉侧：只有当路线需要提前判断障碍时，再借鉴第三、四篇加入深度输入与蒸馏，明确新增计算和延迟成本。

最终对比时固定训练预算、随机种子、测试路线、硬件限制和 checkpoint 选择方法，至少报告多次测试的均值与波动。若把训练课程和奖励一起更改，就只能说“整套方案有效”，不能单独归因给 MoE 或某个奖励。

5. 一段可以直接带去和学长讨论的表述

我准备先复现第一篇的本体感知 MoE 运动控制，把它定位为巡检机器人的低层速度跟踪 baseline。训练保留教师特权信息，部署只用学生历史观测；用跨模拟器测试和实机低速任务检验跟踪、晃动、能耗和受扰恢复。第二篇帮助我理解历史适应与命令课程，第三、四篇则作为后续视觉越障和时序蒸馏的参考。先确认平台适配与 baseline 性能，再选择一项与巡检场景直接相关的稳定性改进做消融。

自测：为什么不先给巡检机器人上“极限跑酷”？

任务目标决定需要的能力。极限跳跃的训练地形、奖励与电机负担，不自动等于长时间巡检所需的低速平顺、精准停车和可靠导航。先构建任务匹配的运动 baseline，再按路线需求加技能，更容易验证改进究竟解决了什么问题。
